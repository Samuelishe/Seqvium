# Neon Orchard

Neon Orchard is Seqvium's official evolving demo composition. It is a living example of the
application, a musical project for checking instruments, DSP, Mixer and editors, and a reference
for comparing playback and WAV export between application versions. We will write, arrange and
improve it toward a complete track. The present 32 bars are a starting point.

## Open, play and export

After [building and launching Seqvium](../../README.md#getting-started), click **Open** and select
[Neon Orchard.seqvium](Neon%20Orchard.seqvium). Everything needed is included in a normal clone;
there is no sample-library download, generator run or third-party plugin installation step.
Keep `Neon Orchard.seqvium` and its sibling `Neon Orchard.seqvium.media` directory together.
Opening stays silent until you press Play.

Open **Playlist** from the left rail or Panes menu, press **Start**, leave range looping off and
press **Play** for the whole Song. Stop ends playback. In Channel Rack choose a Pattern and use
its Play control for a continuous Pattern loop. Open Piano Roll from a channel's actions to edit
notes; **Open sound editor** shows the drum parameters or sampled Source. **Mixer** contains the
saved channel assignments, Drums bus, EQ, compression and Master protection.

Use **Playlist → Export WAV** for the whole composition. Choose a destination outside managed
media, preferably outside the checkout. Current export is 48 kHz stereo PCM16, with graph and
Mixer processing. Use **Save As** outside the checkout for personal experiments; it copies managed
media and leaves the official project available for comparison. The demonstrated desktop/audio
environment is Windows 11; Linux/macOS runtime support remains unverified.

## Current composition

The publication baseline is 112 BPM, 4/4, 32 bars (about 68.571 seconds), 15 Patterns, 19 Parts,
191 notes and 78 Playlist clips on nine named tracks. Seven built-in synthesized drum families,
sampled bass, upright piano, pizzicato violin, flute and an electronic transition feed 12 instrument
Mixer channels, a Drums bus and Master. These are editable notes, instruments, graphs and Mixer
state; the project is not a flattened recording.

The public edition preserves the source composition's notes, Pattern identities and lengths,
Playlist, local graph gains, instrument parameters and entire Mixer. It replaces only the two
MusicRadar sound sources: both bass uses now share **Neon Bass A1**, and FX uses **Neon Transition FX**.
The bass is a rounded A1 harmonic synth; FX is an original falling chirp with metallic partials
and deterministic filtered noise. Their timbres differ from the private edition. Existing Root Pitch,
note gates and musical roles stay intact. Identical WAV copies share immutable locators; all nine
resource identities remain. The source project, private library and private mix were not modified.

## Resources and licenses

There are six unique WAVs, 8,657,108 bytes in total. [MEDIA.json](MEDIA.json) is the complete file
inventory with relative locators, SHA-256, byte counts, origins and license identifiers.

| WAV content                                                                             | License    | Origin                                                                                               |
|-----------------------------------------------------------------------------------------|------------|------------------------------------------------------------------------------------------------------|
| Neon Bass A1; Neon Transition FX                                                        | Apache-2.0 | Original mathematical synthesis in [generate-sounds.py](generate-sounds.py), with no input recording |
| Upright piano A3; flute expressive vibrato A3; solo violin pizzicato A3 piano and forte | CC0-1.0    | VSCO 2 Community Edition, exact upstream bytes                                                       |

The soft pizzicato is a retained unused project resource; the current Glass Seeds sound uses forte.
Built-in Kick, Snare, Closed/Open Hat, Clap, Tom and Rim reconstruct from project parameters and
require no media files. The Seqvium composition, project additions and generator follow the root
[Apache-2.0 license](../../LICENSE). VSCO recordings retain their own CC0 dedication; they are not
relicensed as Apache-2.0. The bundled [VSCO CC0 text](licenses/VSCO2-CE-CC0.txt) and
[third-party ledger](../../docs/THIRD_PARTY.md#neon-orchard-demo-media) supply attribution and evidence.

The generator is optional maintenance material: `python "examples/Neon Orchard/generate-sounds.py"`
reproduces the two original sounds with Python's standard library. It refuses to replace accepted
audio if the generated bytes differ. Checked-in WAVs are the playback source of truth.

## Developing one main demo

Edit `Neon Orchard.seqvium` in place for official musical development, and review project plus media
together. Keep one main composition, rather than accumulating `final`, `new`, `v2` or alternate mixes.
Changes to tools should exercise this composition; they need not change its music. Future creative
work can extend sections, introduce instruments and improve arrangement and mixing as features mature.

Before a substantial musical revision, freeze the previous project as a named JSON snapshot in
`checkpoints/`, record its purpose, project hash, application version and export conditions in the
[checkpoint register](checkpoints/README.md), and retain every immutable media file it references.
Small corrections use ordinary reviewed Git history once the owner chooses to commit them. New or
replaced media needs a license/provenance entry before inclusion; do not delete media still needed
by a checkpoint or pretend resampling clears source rights.

To materialize the initial reference as an independently editable project, run from the repository root:

```powershell
& 'examples/Neon Orchard/Restore-Checkpoint.ps1' `
  -Snapshot 'examples/Neon Orchard/checkpoints/publication-01.json' `
  -Destination 'C:/Temp/Neon Orchard publication-01'
```

The destination must be new. The script validates locators and hashes, copies the frozen JSON and
only its required WAVs together with the inventory and license texts, and never overwrites an existing
project. Compare the same snapshot on two
application versions to study engine changes; compare two snapshots on the same application version
to study musical changes. Match sample rate, export format, full Song bounds, Mixer settings and
cold-start playback. A changed WAV hash is evidence of a difference, not a judgment of sound quality.
Keep routine exports and GUI screenshots outside Git; preserve a reference render only for a concrete
comparison need with its settings and media provenance.
